# Use Cases

The protocol is domain-agnostic at the core and domain-specific at the profile/skill layer.

## Business Strategy

Examples:

- market selection;
- capital allocation;
- pricing;
- product direction;
- go-to-market;
- competitor analysis.

The system should emphasize alternatives, assumptions, disconfirming evidence, value of information and real-world validation.

## Software Engineering

Examples:

- diagnose and fix defects;
- architecture changes;
- testing;
- deployment;
- rollback.

The system should emphasize code evidence, tests, change boundaries, approvals and production safety.

## Infrastructure / DevOps

Examples:

- server changes;
- networking;
- hosting operations;
- deployment automation.

The system should emphasize privilege boundaries, idempotency, rollback, environment scope and recovery.

## Cybersecurity

Examples:

- configuration review;
- vulnerability remediation;
- policy enforcement.

The system should emphasize authorization, auditability, least privilege, isolation and independent verification.

## SEO / Marketing / Sales

The system can use domain-specific evidence and outcome periods while retaining the same core lifecycle.

## Research / Data Analysis

The system should distinguish observation, external evidence, inference, assumption and unknowns.

## Domain profile concept

A domain profile may define:

- preferred reasoning methods;
- relevant risks;
- required evidence;
- accepted tools;
- default acceptance patterns;
- critic checks;
- escalation rules;
- prohibited actions.

The governed core remains unchanged.
